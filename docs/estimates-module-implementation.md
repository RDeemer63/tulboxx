# Tulboxx Estimates Module: Implementation Guide

**Last Updated:** July 15, 2025

This document provides a comprehensive overview of the architecture, form structure, AI integration, and mobile optimization of the Tulboxx Estimates Module. It serves as the primary guide for developers working on or extending this module.

---

## 1. Architecture Overview

The Estimates Module is built on a modern, component-based architecture designed for flexibility, scalability, and maintainability.

| Layer | Technology / Pattern | Purpose |
| :--- | :--- | :--- |
| **Main Container** | `CreateEditEstimateDrawer.tsx` | A full-screen sheet component that orchestrates the entire estimate creation/editing process. |
| **Form Management**| `react-hook-form` + `zod` | Provides robust, type-safe form state management and validation for both client and server. |
| **State Management**| `React Query` & `Zustand` | `React Query` handles server state (fetching/caching), while `Zustand` manages global UI state where needed. |
| **Component Structure**| Modular Tabs | The form is broken into logical tabs (`ClientJobDetailsTab`, `ScopePricingTab`, `TermsDeliveryTab`) to manage complexity. |
| **Backend API** | RESTful Endpoints | The frontend communicates with a set of dedicated API routes (`/api/estimates/...`) that are handled by the `EstimateRepository`. |
| **AI Integration** | `PromptBuilder` Service | A centralized service that constructs dynamic, context-aware prompts for OpenAI, keeping prompt logic separate from UI components. |

## 2. Form Structure & UX Flow

The estimate creation process is guided by a multi-tab form that adapts its content based on user choices.

### 2.1 Tab 1: Client & Job Details

This tab captures the foundational information for the estimate, pre-filling data from a lead record whenever possible.

| Section | Component / Field | Key Features & UX |
| :--- | :--- | :--- |
| **Client Info** | Accordion Section | Collapsible on mobile. Pre-fills `Contact Name`, `Phone`, `Email`, and `Address` from the lead. Includes a "Send Updates Via" toggle for future notifications. |
| **Job Info** | Accordion Section | Auto-generates `Estimate Title` (e.g., "Tree Removal – John Smith"). `Expected Timeline` is a free-text field with an AI-assist button. |
| **Estimate Format**| Visual Radio Toggle | Users choose between "Simple (One-Price)" and "Detailed (Line Items)". This choice dictates the content of the next tab. The default is "Simple" and the user's last choice is remembered. |

### 2.2 Tab 2: Scope & Pricing

This tab dynamically changes based on the "Estimate Format" selected.

#### If "Simple Estimate" is chosen:

| Component | Key Features & UX |
| :--- | :--- |
| **ScopeEditor** | A large textarea for the scope of work with contextual AI buttons ("Generate", "Improve", "Add Exclusions"). |
| **PricingInputs** | A section for `Base Price` and optional, repeatable `Add-ons` (e.g., "Haul away debris - $150"). |
| **ConvertToDetailed**| A prominent button allows the user to switch to the line-item view, preserving the current scope and price as the first line item. |

#### If "Detailed Estimate" is chosen:

| Component | Key Features & UX |
| :--- | :--- |
| **LineItemToolbar**| Buttons to `+ Add Line Item` and `+ Add Section Header`. A `Save as Template` button is also available. |
| **LineItemContainer**| A drag-and-drop list (`dnd-kit`) where users can reorder items and sections. |
| **LineItemRow** | **Mobile-First Design**: Collapsible rows show a summary (description & total) and expand on tap to reveal all fields (quantity, unit price, etc.). |
| **PricingSummary** | A sticky or footer-docked summary that shows `Subtotal`, `Discount`, `Tax`, and `Total` in real-time. |

### 2.3 Tab 3: Terms & Delivery

This tab finalizes the estimate with legal terms and delivery options.

| Section | Key Features & UX |
| :--- | :--- |
| **Financial Terms**| Toggles for `Require Deposit` (with % or $ inputs) and `Set Expiration Date` (defaults to 30 days). A dropdown for `Payment Terms` pulls from business profile defaults. |
| **Legal & Notes** | `Terms & Conditions` are pre-filled from the business profile but are editable per-estimate. A "Message to Client" field is also available. |
| **Delivery Options**| Buttons to `Preview What the Client Will See`, `Send via Email`, `Get Shareable Link`, and `Download PDF`. |

### 2.4 Sticky Footer

A persistent footer ensures key actions are always accessible:
*   **Left**: `Save Draft` (subtle, outline button)
*   **Center**: `Preview` (icon-only button with a tooltip)
*   **Right**: `Send to Client` (prominent, primary action button)

## 3. AI Integration

AI assistance is designed to be a helpful enhancement, not a requirement.

*   **`PromptBuilder` Service**: All AI prompts are generated by this centralized service, which takes in context like `serviceType`, `customerName`, and `brandVoice`. This makes our AI prompts modular and easy to update.
*   **Contextual Placement**: AI-assist buttons (`<Wand2 />`, `<Sparkles />`) are placed directly next to the fields they enhance (Scope of Work, Line Item Descriptions).
*   **Refined Prompts**: Prompts are tailored to trade-specific scenarios, such as:
    *   `"Add estimated start and completion dates, including permitting or material lead times if relevant."`
    *   `"Summarize a trenching job for a driveway runoff fix, including excavation, pipe installation, and backfilling."`

---

## 4. Mobile Optimization

The entire form is built with a mobile-first philosophy.

| Feature | Implementation |
| :--- | :--- |
| **Layout** | A single-column, scrollable layout on mobile that expands to a multi-column view on desktop. |
| **Line Items** | Collapsible rows prevent vertical clutter. Users tap to expand and edit a single item at a time. |
| **Sticky Footer**| Ensures primary actions are always accessible without scrolling, and collapses on scroll-down to maximize screen real estate. |
| **Tap Targets** | All interactive elements (buttons, inputs, toggles) are designed with a minimum height of 44px to be easily tappable. |

## 5. Running & Testing the Implementation

To ensure the Estimate Capture Form is working as expected, follow the QA checklist below.

### 5.1 How to Run the Test Environment

1.  Open your terminal in the project root directory.
2.  Ensure all dependencies are installed with `npm install`.
3.  Run the verification script:
    ```bash
    ./verify-client-changes.sh
    ```
4.  This will start the development server and open the application in your browser, navigating directly to the estimates page.
5.  Log in with a test user account if prompted.
6.  Click the "Create New Estimate" button to open the form and begin testing.

### 5.2 QA Checklist

#### Tab 1: Client & Job Details
- [ ] **Default Title**: Confirm the estimate title auto-populates based on the service type and client name.
- [ ] **Timeline Field**: Test the free-text input for 'Expected Timeline' and click the AI assist button.
- [ ] **Estimate Format Toggle**: Verify that switching between 'Simple' and 'Detailed' works and changes the next tab.
- [ ] **Accordion Sections**: Check if the 'Client Information' and 'Job & Estimate Details' sections collapse and expand.

#### Tab 2: Scope & Pricing (Simple Estimate)
- [ ] **AI Scope Buttons**: Test the 'Generate' and 'Improve' AI buttons. Confirm they log prompts to the console.
- [ ] **Pricing Inputs**: Add a base price and optional add-ons. Verify the total updates in real-time.
- [ ] **Totals Animation**: Check for the subtle green/red flash on the total when prices change.
- [ ] **Totals Tooltip**: Hover over the 'Total' value to see the calculation breakdown.
- [ ] **Convert to Detailed**: Click the 'Switch to Detailed' button and confirm the view changes and data is preserved.

#### Tab 2: Scope & Pricing (Detailed Estimate)
- [ ] **Add Items**: Use '+ Add Line Item' and '+ Add Section Header' buttons.
- [ ] **Drag-and-Drop**: Reorder line items and sections. Confirm the UI updates smoothly.
- [ ] **Mobile View**: Resize the browser to a mobile width. Test the collapsible line item rows (tap to expand/collapse).
- [ ] **Real-time Totals**: Change quantity and price on a line item and verify the main pricing summary updates.
- [ ] **Last Item Summary**: In collapsed mode on mobile, confirm only the description and total are visible.

#### Tab 3: Terms & Delivery
- [ ] **Deposit Toggle**: Enable the 'Require Deposit' switch and test the percentage vs. fixed amount inputs.
- [ ] **Expiration Toggle**: Verify the expiration date is on by default and can be changed.
- [ ] **Terms Pre-fill**: Check that 'Terms & Conditions' are pre-filled (from business profile defaults).
- [ ] **Delivery Buttons**: Test the 'Preview', 'Send', and 'Download' buttons. Confirm tooltips appear.

#### Sticky Footer
- [ ] **Visibility**: Confirm the footer with 'Save Draft' and 'Send to Client' is always visible.
- [ ] **Scroll Behavior**: On a long form, scroll down and up. Check if the footer collapses or hides as expected.
